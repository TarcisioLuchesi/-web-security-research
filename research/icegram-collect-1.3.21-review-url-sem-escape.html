WordPress / static analysis / unescaped sink

Icegram Collect 1.3.21

Tracing review_url from admin_notices to an unescaped HTML meta-refresh attribute, with important exploitability constraints.

PHPWordPressReflected HTML injectionNo external impact demonstrated
2026-11-01Static analysisAI-AssistedCVE: not assigned

Evidence scope: This is a static review of the 1.3.21 package. The inspected HTML sink accepts review_url without attribute escaping, but the normal path requires an eligible administrative screen, manage_options, at least two published leads, and a valid nonce. Exploitation by an external or low-privilege user was not demonstrated. No CVE, severity score, browser execution, or affected-version range is asserted.

Rainmaker::__construct() → feedback class → admin_notices → show_review_notice() → screen/capability filter → review nonce/action → $_GET['review_url'] → meta refresh content attribute

Summary

The review notice reads review_url from the query string and places it directly inside a quoted content attribute of <meta http-equiv="refresh">. A double quote could terminate that attribute and allow additional markup. However, reaching the sink under default conditions requires administrator privileges and the correct nonce. I found no demonstrated way for a visitor or Subscriber to obtain another user's administrative nonce.

1. From constructor to hook

The Rainmaker constructor loads the feedback class and initializes it with the ig_rm prefix:

$ig_feedback_class = 'IG_Feedback_V_' . str_replace( '.', '_', $feedback_version );
$ig_rm_feedback    = new $ig_feedback_class( 'Rainmaker', 'icegram-rainmaker', 'ig_rm', 'rmfree.', false );

The feedback constructor registers show_review_notice() under admin_notices when the feedback widget is enabled:

if ( ! $this->can_show_feedback_widget() ) {
    return;
}
add_action( 'admin_notices', array( &$this, 'show_review_notice' ) );

This hook is how the input-handling code is reached during an administrative page render.

2. Who can reach the notice

The eligibility filter requires the appropriate Icegram Collect screen, the manage_options capability, and at least two published leads:

$screen = get_current_screen();
if ( ! in_array( $screen->id, array( 'edit-rainmaker_form', 'rainmaker_form', 'edit-rainmaker_lead', 'rainmaker_form_page_icegram-rainmaker-support', 'rainmaker_form_page_icegram-rainmaker-upgrade' ), true ) ) {
    return false;
}
if ( ! current_user_can( 'manage_options' ) ) {
    return false;
}
$total_rm_leads         = wp_count_posts( 'rainmaker_lead' );
$total_rm_leads_publish = $total_rm_leads->publish;
if ( $total_rm_leads_publish < 2 ) {
    return false;
}

User metadata, including ig_rm_feedback_review_done, can suppress the notice once a response has been recorded. Ordinary visitors and Subscribers do not satisfy the default privilege check.

3. How the nonce enters the URL

The plugin generates a nonce for the review action and builds the evaluation link with the nonce, action, and a review destination:

$nonce = wp_create_nonce( 'review' );
$review_url = add_query_arg( 'review_url', $review_url, add_query_arg( 'ig_feedback_nonce', $nonce, add_query_arg( 'ig_feedback_action', $review_done_option, $current_page_url ) ) );

The ordinary destination is the plugin's review page on WordPress.org, and the nonce is included in HTML shown to the eligible administrator.

4. From query string to output sink

The action handler verifies ig_feedback_nonce before proceeding:

$nonce_verified = wp_verify_nonce( $nonce, 'review' );
if ( $nonce_verified ) {
    $action = ! empty( $_GET['ig_feedback_action'] ) ? esc_attr( wp_unslash( $_GET['ig_feedback_action'] ) ) : '';

The action must also match ig_rm_feedback_review_done; it changes the user's metadata. Then it reads $_GET['review_url'] and inserts the value into an HTML attribute without escaping:

$url = ! empty( $_GET['review_url'] ) ? $_GET['review_url'] : '';
if ( ! empty( $url ) ) {
    ?>
    <meta http-equiv="refresh" content="0; url=<?php echo $url; ?>"/>
    <?php
}

This is a definite escaping problem in the reviewed code. JavaScript execution in a browser was not established in this analysis.

5. Evidence limitations

A local dynamic test would require an eligible admin session, the visible notice, and that user's nonce. Following the review action marks the notice as complete, complicating repeated tests with the same user. The static finding alone does not prove a low-privilege attack chain.

6. Impact and remediation

Generate the review URL on the server instead of trusting a query parameter. If the parameter remains necessary, allowlist scheme and host, then escape the complete value at the exact attribute output sink. Regression tests should cover quotes and tags, invalid nonces, and requests without manage_options.

Conclusion

The source-to-sink path documents an unescaped attribute in version 1.3.21; the demonstrated privilege and nonce constraints prevent claims of confirmed external exploitation.
