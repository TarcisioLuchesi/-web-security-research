WordPress / stored XSS / patch analysis

Paytium 5.0.3 → 5.0.5

A discount code was rendered without output escaping in the administration panel in 5.0.3; the fix was verified in 5.0.5.

Stored XSS WordPress PHP Admin UI fixed in 5.0.5
Research: Tarcísio Luchesi (Poystick) Environment: authorized lab CVE: not assigned

This is a regression analysis comparing Paytium versions 5.0.3 and 5.0.5. I examined whether attacker-controlled discount data reached an unsafe HTML sink and whether the newer version prevented that behavior.

Finding: Paytium 5.0.3 rendered stored discount codes in an administration screen without HTML escaping. The reviewed 5.0.5 code uses esc_html() at the same sink. This case is documented as fixed, and no new CVE is claimed.

The vulnerable flow in 5.0.3

During payment processing, the plugin builds discount information from the submitted form, including the discount_code field:

$discount_data = array(
    'discount_code' => $_POST['pt-discount']['code'],
    // ...
);

The value is persisted with the payment details. Later, the subscription detail screen retrieves it using $payment->get_discount_code() and concatenates it directly into HTML:

echo $payment->get_discount_value()
    . ' (code: ' . $payment->get_discount_code() . ')';

This output is the final sink. The browser can interpret user-controlled markup in an administrator's page rather than displaying it as text.

Discount code input → payment data → persisted payment → get_discount_code() → subscription-details.php output → admin HTML

Fix verified in version 5.0.5

The same sink was changed to apply contextual HTML escaping:

echo esc_html(
    $payment->get_discount_value()
    . ' (code: ' . $payment->get_discount_code() . ')'
);

Escaping at the output prevents previously stored special characters from being interpreted as active HTML in that view.

Safe laboratory PoC

I validated the behavior only in a controlled installation using a simple HTML marker:

<img src=x onerror=alert(document.domain)>

In 5.0.3, the stored value reached the subscription view as markup. In 5.0.5, the expected behavior is escaped text rather than script execution. The PoC does not involve cookies, secrets, or testing third-party systems.

Remediation practices

Escape data for its exact output context: esc_html() for text nodes, esc_attr() for HTML attributes, and esc_url() for URLs. Validate input structures, allowlist permitted metadata keys, and trace persisted data to every output sink.
