Research hypotheses

How I develop, question, and test hypotheses in web security, using independent reasoning and AI for analysis, comparison, and learning.

Evidence standard: A hypothesis is not a confirmed vulnerability. Observations, laboratory reproductions, and demonstrated results must be distinguished from unverified possibilities. AI does not replace that validation.

Independently developed hypotheses

My investigation starts with an original observation: user-controlled input, a trust boundary, or unexpected behavior. I propose a mechanism, attempt to disprove it, and document exactly what the experiment shows.

  1. Observe functionality and actual behavior.
  2. Formulate a testable causal hypothesis.
  3. Design a controlled test and consider counterexamples.
  4. Record evidence, limitations, and conclusions.

Example research direction

HTML Injection / CSRFHypothesis tested in a local scenario

HTML Injection and trust in the Origin header

Question: If an HTML form is injected into an application, could the browser submit a state-changing action with that application's own origin, even if a form hosted elsewhere would be blocked?

Reasoning: A defense that only compares Origin headers does not necessarily distinguish a legitimate interface from a malicious form inserted into the same document.

Limitation: The effect depends on the available action, the victim's permissions, and other protections. It does not automatically establish account takeover. A local test cannot confirm the issue in an arbitrary real-world application.

Related reading: OWASP Web Security Testing Guide.

What I document for each independent hypothesis

  • Original observation and authorized context.
  • Assumptions, proposed mechanism, and expected result.
  • Test procedure and reproducible evidence.
  • Counterexamples, results, and confidence level.

AI-assisted hypotheses

I define the problem and use AI to explore alternatives, review code paths, and challenge assumptions I may have overlooked. The goal is to strengthen critical thinking, not outsource conclusions. Each suggestion must be checked against code and independent testing.

  1. Describe the behavior and technical question.
  2. Ask AI for alternative hypotheses and objections.
  3. Manually verify code, requests, and conditions.
  4. Separate unproven suggestions from validated evidence.
